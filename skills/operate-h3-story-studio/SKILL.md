# Operate H3 Story Studio

Treat Project Core as the source of truth and the existing H3 Studio as the renderer. Bind every action to one exact project ID, session, revision, digest, and focus before reading or changing story data. Keep H3's Japanese/community prompt flow intact when changing its UI or defaults.

## Fixed local boundary

- Work only on Windows under `C:\PROJECT_HUB`.
- Use the product root `C:\PROJECT_HUB\NIKU-STUDIO-FOR-WORK\drama-studio`.
- Keep `C:\PROJECT_HUB\NIKU-STUDIO-FOR-WORK\h3_oss` on its pinned H3/ComfyUI route. Do not patch it unless the user explicitly authorizes a renderer/UI/default change; when authorized, preserve its prompt flow, model pins, and contracts and verify the H3 tests.
- Use Story Sidecar `http://127.0.0.1:7864`; let it mediate H3 at `http://127.0.0.1:7863`.
- Use the human UI at `http://localhost:3000`.
- Never treat a title, browser tab, current directory, or the most recent output as sufficient project identity.

Stop and report a boundary failure if the machine, paths, ports, project ID, or handoff do not match these constraints.

## Start or inspect the stack

Run from the product root:

```powershell

python scripts\storyctl.py health
```

If the stack is unavailable, run:

```powershell

```

Use `Start-H3-Story-Studio.cmd` when the user wants the UI opened. Do not kill or restart healthy listeners merely to obtain a clean process.

## Start a story from zero

Use this only when the user asks to create a Project. Do not seed UI fixtures or copy an existing Project.

1. Write a UTF-8 Project spec inside `C:\PROJECT_HUB\NIKU-STUDIO-FOR-WORK\drama-studio\work` using the create contract in [contracts.md](references/contracts.md).
2. Create the runtime scaffold:

```powershell
python scripts\storyctl.py create-project --spec-file <PROJECT_SPEC_JSON>
```

3. Capture the server-generated `projectId`, `projectRoot`, Revision 0, digest, and exact Episode/Scene/Shot/Prompt focus. Activate that ID immediately; never infer it from the title or code.
4. Fetch context, then replace the complete scaffold Shot and Prompt payloads with the smallest story proposal. Preserve unknown fields and use the exact Revision CAS.
5. For an AI bitmap, trigger the installed `imagegen` skill. When the user explicitly requires GPT-image-2, use its documented CLI/model-control path and require `OPENAI_API_KEY`; never silently substitute another model. Keep the temporary output under `work/generated-assets/<projectId>/` until upload.
6. Add a metadata asset or upload the real image/video/audio file using `storyctl.py add-asset` and the asset contract. Set `source` to `codex_gpt_image_2` only for a file actually generated by that model; otherwise use `human`.
7. Re-fetch context after every successful creation/upload because each asset advances the Project Revision. Use the returned server asset ID in Prompt `reference_asset_ids`.
8. Before the script/prompt pass, create the project thumbnail from the registered character, environment, and prop references. Use the installed `imagegen` skill with a 16:9 landscape composition, the exact project title as the only prominent text, and a YouTube-thumbnail-like layout. Preserve adult character identity and keep logos, watermarks, brand names, and extra text out.
9. Copy the generated image to `work/generated-assets/<projectId>/`, register it as a locked `reference` asset named `プロジェクトサムネイル` with `source=codex_gpt_image_2` (or `human` for a human upload), and verify its dimensions, byte hash, and appearance in the WebUI. Use the returned asset ID as the project thumbnail reference; do not treat it as an H3 shot reference unless the user asks.
10. Build the authoring Prompt with exact `@素材名` mentions. Story Studio resolves those mentions to formal H3 bindings; the existing H3 Studio `community` planner performs Japanese/H3 prompt formatting. Do not add a second translation or prompt-planner layer in Story Studio or Codex.
11. Submit one low-cost real H3 take, poll, sync, verify its registered artifact, then continue the human/Codex revision loop.

For a metadata-only asset, omit `--file`. For an uploaded asset:

```powershell
python scripts\storyctl.py add-asset `
  --project-id <PROJECT_ID> `
  --session-id <SESSION_ID> `
  --expected-revision <REVISION> `
  --spec-file <ASSET_SPEC_JSON> `
  --file <LOCAL_MEDIA_PATH>
```

## Activate exactly one project

1. Run `python scripts\storyctl.py projects`.
2. Resolve the intended project to an exact `projectId`. If multiple projects could match the request, ask the user; do not guess.
3. If given a handoff capsule, read it first. Extract `projectId`, `projectRevision`, `stateDigest`, `focus`, and `projectRoot`; reject a path outside the product root.
4. Activate with a descriptive agent ID:

```powershell
python scripts\storyctl.py activate --project-id <PROJECT_ID> --agent-id codex-<short-task>
```

5. Copy the returned `sessionId`, then fetch context:

```powershell
python scripts\storyctl.py context --project-id <PROJECT_ID> --session-id <SESSION_ID>
```

6. Verify all of the following before work:
   - response `projectId` equals the requested ID;
   - `isCurrent` is true;
   - `revision`, `currentProjectRevision`, and the session binding agree;
   - `stateDigest` agrees with the binding and, when supplied, the handoff;
   - `focus` points to existing entities;
   - `projectRoot` stays beneath the product root.

7. State the active project title/ID, revision, digest prefix, focus, selected take, pending approvals, pending `agent_request` IDs, and intended next action. Use the exact marker `H3STORY_ACTIVATED` so handoffs and logs are easy to recognize.

Do not continue a stale handoff silently. If its revision or digest differs, activate current state, explain the divergence, and require a fresh proposal against the new revision.

## Read, propose, then commit

Use this sequence for script, asset caption, lock, prompt, focus, approval, and take-selection changes:

1. Fetch current context immediately before editing.
2. Preserve locked or approved content unless the user explicitly requests that exact change.
3. Show a concise proposal: targets, before/after intent, continuity impact, and render impact.
4. Build the smallest atomic operation list. An entity upsert replaces its entire payload, so preserve all required and unknown fields.
5. Read [contracts.md](references/contracts.md) before constructing patch or render JSON.
6. Commit with the session's exact current revision. Never invent, decrement, or force a revision.
7. Verify the returned revision and digest, then fetch context again if subsequent work depends on the change.

Use `storyctl.py patch` with an operations file for non-trivial edits. Keep temporary operation files inside `C:\PROJECT_HUB\NIKU-STUDIO-FOR-WORK\drama-studio\work`; do not place them in the H3 repository.

On HTTP 409 or `REVISION_CONFLICT`, stop the mutation loop. Re-activate, inspect the new context, recompute the proposal, and never replay the stale payload automatically.

For a pending `agent_request`, treat its persisted `request` text as the Web UI user's task within the entity's exact project/focus. If several are pending, list them and ask which to handle rather than silently choosing. When work is genuinely finished, update that request to `status: completed` in the same atomic patch as its resulting Project changes; do not mark it completed for a proposal-only response.

## Generate and review an H3 take

Before authoring or submitting a Japanese dialogue prompt, read
[prompt-safety-and-dialogue.md](references/prompt-safety-and-dialogue.md). Before
choosing a continuity mode, read
[i2v-omni-selection.md](references/i2v-omni-selection.md). Use the error-specific
repair rules in [failure-cookbook.md](references/failure-cookbook.md) instead of
blindly retrying a terminal failure.

1. Confirm the focused shot and persisted prompt from Project Core.
2. Treat `@素材名` as Story Studio authoring syntax, not H3 wire syntax. Exact file-backed mentions become `<Picture N>`, `<Video N>`, or `<Audio N>` according to the submitted reference order; metadata-only mentions become descriptive context. Unknown or ambiguous mentions must fail before a revision or H3 submission.
3. Keep `prompt_processing_mode` as `community`. Story Studio may bind mentions deterministically, but must pass the resulting Japanese/formal-reference Prompt through the existing H3 Studio community flow.
4. Run `python scripts\storyctl.py h3-state`; require a compatible ready state.
5. Submit through `storyctl.py render`, not directly to H3.
6. Record `localJobId`, `h3JobId`, `takeId`, and the returned project revision.
7. Poll only that exact H3 job with `storyctl.py job` until terminal. Treat `progress` as either 0–1 or 0–100.
8. Do not mutate the project while the job is pending; otherwise sync may correctly conflict.
9. On completion, run `storyctl.py sync` with the render-submission revision and download enabled.
10. Verify the registered video asset path, byte size, and SHA-256 under that project's `outputs/<shot>/` directory.
11. Inspect the Project job intent: retain `authoring_prompt`, `resolved_prompt`, effective `community` mode, ordered reference bindings, source path/size/hash, and the exact H3 job ID.
12. Treat a new take as a candidate. Adopt it only when the user requested automatic selection or after review; selection is another revisioned patch.
13. Re-fetch context and report the final revision, selected take, artifact path, and whether another revision loop is advisable.

Before submitting, expose and honor the same generation controls as H3 Studio:
style; aspect ratio and the H3 resolution catalog (Preview/SD/HD/Native);
124/243/345 frames; Draft/Standard/High sampling steps (8/20/30); seed;
EasyCache acceleration; reference image size; `community`/`raw_en` prompt
processing; standalone-audio policy; audio preset; BGM policy; gain; dialogue;
and soundscape. Read the H3 `/api/state` capabilities when available so the
resolution catalog is not duplicated as a hidden second source of truth. These
values must populate the actual render request and the persisted job intent;
disabled or decorative controls are not considered implemented. If `raw_en` is
selected, enforce H3's contract by using natural style, empty dialogue and
soundscape, auto audio/BGM, and no auxiliary audio overrides.

H3's current acceleration default is `community` (おすすめ：控えめ・通常),
which uses the restrained published EasyCache preset. Keep `off` (高速化なし・
比較用), `conservative` (より慎重・品質優先), and `balanced` (速度優先・
品質を確認) visible as explicit choices. H3 automatically disables EasyCache
for Draft jobs below 12 steps; surface that automatic behavior in the UI and in
the persisted job intent rather than presenting a numeric percentage alone.

### Optional clip-to-clip continuity handoff

Keep this a per-render choice named `carryOverEndFrame` (default `false` for
independent shots; the UI may default it to `true` when the next shot should
continue the previous one). The choice must be visible to the human operator.

- When the choice is off, submit the next shot with its normal reference assets
  and `uploads.first_image_asset_id = null`.
- When the choice is on, never submit the next shot until the predecessor's H3
  job reaches a terminal state. Sync it with `storyctl.py sync --extract-end-frame`.
  The Sidecar downloads the MP4, extracts the last decoded frame with the local
  ffmpeg runtime, registers a locked Project image asset, and returns its
  `endFrameAssetId` together with the video artifact.
- After a human/Codex review checkpoint, submit the next shot with
  `uploads.first_image_asset_id = <endFrameAssetId>`. Keep that end-frame asset
  out of `reference_asset_ids`; it is the dedicated first-frame upload. H3 still
  receives the resulting Japanese/formal-reference Prompt through its existing
  `community` flow.
- H3's pinned upload contract forbids first/last frame slots in `omni`. When a
  carry-over first frame is present, use `i2v` with an empty
  `reference_asset_ids` array (the character/prop descriptions remain in the
  Japanese authoring Prompt). Use `omni` only for the normal ordered-reference
  path with no first/last slot.
- Record the predecessor take ID, extracted asset ID, image path, dimensions,
  and SHA-256 in the handoff/report. If extraction or registration fails, stop
  before the next H3 submission rather than silently falling back to a blank
  first frame. A human may turn the choice off and intentionally render an
  independent cut.

## Candidate review, selected timeline, and downloads

Read [qa-and-assembly.md](references/qa-and-assembly.md) before adopting a take
or declaring a long-form render complete. A completed H3 job is only a candidate:
run structural, visual, audio, and continuity gates, then select exactly one
ready take per shot in Project Core.

The video-production UI must expose that same state rather than inventing a
second fixture list:

- the right candidate rail shows a real first-frame (or equivalent) thumbnail
  for every generated take, its state, and a one-click browser download;
- the bottom timeline shows the selected take thumbnail for every shot, marks
  `採用`, focuses the shot on click, and provides a download for the selected
  artifact;
- missing artifacts use a visibly neutral placeholder and are never presented
  as generated media.

For a complete sequence, export the current context and run the bundled audit:

```powershell
$contextJson = python scripts\storyctl.py context --project-id <PROJECT_ID> --session-id <SESSION_ID>
$contextJson |
  python C:\Users\NIKU_\.codex\skills\operate-h3-story-studio\scripts\audit_selected_takes.py `
    --context-file - `
    --project-root <PROJECT_ROOT> `
    --width <WIDTH> `
    --height <HEIGHT>
```

Use `--concat-output <PROJECT_ROOT>\outputs\final-derived.mp4` only after the
audit is clean. Keep the selected takes and end-frame assets as the canonical
Project Core entities; treat the concatenated file as a derived output unless
the current asset contract explicitly provides a derived-video category.

If H3 is offline, distinguish a UI demo take from a real H3 artifact. Never present a demo as generated media.

## Coordinate with the human UI

- The first preparation checkpoint is the project thumbnail: verify 16:9 dimensions, title readability, correct project ID, registered source/hash, and that the WebUI displays it before starting H3 generation.
- Human caption, asset, script, and prompt edits use explicit save controls; take adoption also creates a revision. Never treat unsaved UI state as Project Core state.
- The Codex dock stores each submitted message as a pending `agent_request`. It does not pretend that an agent ran inline; `Codexで続ける` transfers the persisted inbox and context to Codex.
- Before continuing after human interaction, fetch context again. Do not rely on a previously rendered UI snapshot.
- Generate an immutable capsule with `storyctl.py handoff` or the UI's `Codexで続ける` action before transferring work to a fresh Codex task.
- Tell the user which project/revision the UI currently shows when proposing a manual review.

## Finish safely

Before declaring completion:

- confirm exact project ID, current revision, digest, and focus;
- confirm every generated take and asset belongs to the focused project/shot;
- confirm one selected ready take per shot and that the candidate rail and
  selected timeline show the same take IDs, thumbnails, states, and download
  targets;
- run the selected-take audit in
  [qa-and-assembly.md](references/qa-and-assembly.md), including the visual and
  audio gates, before assembling a derived sequence;
- confirm no file under the H3 repository changed;
- run the relevant product tests after code changes;
- create a fresh handoff capsule when another Codex task will continue;
- report real artifacts separately from fixtures or demos.
